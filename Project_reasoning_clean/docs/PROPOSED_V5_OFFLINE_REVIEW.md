# รายงานตรวจ Verifier v5 แบบ offline: 0036, 0041 และ 0008

วันที่ตรวจ: 3 ตุลาคม 2026

## ข้อสรุป

พบปัญหาการเลือกและใช้หลักฐานในผลตรวจจริง ไม่ใช่เพียงปัญหา JSON ขาดฟิลด์ ข้อ 0036 และ 0041 มีบทกฎหมายส่วนที่เกี่ยวข้องอยู่ใน context แต่ Verifier เลือกส่วนอื่นมาอ้างและให้ PASS ทั้งหมด ข้อ 0008 มีข้อสรุปหลักตรงกับเฉลยและเลือกกฎหมายตรงประเด็น แต่หลักฐานจากคำถามที่เลือกยังไม่ครอบคลุมเงื่อนไขสำคัญ

ข้อค้นพบนี้รองรับการตรวจปรับกระบวนการเชื่อมข้อกล่าวอ้างกับหลักฐาน ไม่รองรับการบังคับให้มี FAIL หรือสรุปว่าโมเดลไม่สามารถตรวจได้ทุกกรณี

## ขอบเขตและวิธีตรวจ

ตรวจเฉพาะผลและข้อมูลที่บันทึกใน Clean Project ไม่เรียก LLM, Ollama, retriever หรือ evaluator และไม่แก้ prompt, code, config หรือผลทดลองเดิม รายงานนี้เป็นการตรวจความสอดคล้องภายใน dataset/corpus ที่ใช้ทดลอง ไม่ใช่การตรวจสถานะกฎหมายปัจจุบันจากแหล่งภายนอก

อ่านคำถามและเฉลยทั้ง reference_answer และ answer ใน data_splits/tax_engineering_10.csv เทียบกับ draft, feedback และ evidence_index ใน trace ของทั้งสามข้อ เฉลยใช้สำหรับการตรวจภายหลังเท่านั้น ไม่ใช่ข้อมูลที่ Verifier ได้รับ

ตรวจ hash ของ baseline_files ที่บันทึกใน identity เทียบไฟล์ปัจจุบันแล้วไม่พบ mismatch ทั้งสามข้อ ตรวจเส้นทาง runner แล้วพบว่า verdict มาจาก feedback ของโมเดล ไม่มีโค้ดตั้งทุกด้านเป็น PASS โดยอัตโนมัติ ตัวตรวจรูปแบบไม่ใช่ตัวตรวจความหมายของกฎหมาย

เลือก 0036 และ 0041 เพราะมีความต่างจากเฉลยที่เห็นชัด และ 0008 เป็นกรณีเปรียบเทียบที่ข้อสรุปหลักตรงกับเฉลย การเลือกนี้เป็นการวิเคราะห์ข้อผิดพลาด ไม่ใช่ตัวอย่างสุ่มหรือคะแนน benchmark ไม่ควรนำสัดส่วนของสามข้อนี้ไปอ้างแทนทั้ง dataset

## ข้อ 0036: สินค้าอาหารสัตว์สองชนิด

### ร่างตอบอะไร

ร่างวิเคราะห์ว่า GELSYS OPC1 และ Choline Chloride 60% ไม่ได้ถูกระบุชื่อไว้ในมาตรา จึงอาจไม่ได้รับยกเว้น แล้วคำตอบภาษาไทยสรุปชัดว่าทั้งสองชนิดไม่ได้รับยกเว้น

เฉลยแยกสองกรณี: GELSYS ต้องมีเงื่อนไขการรับรองจากกรมปศุสัตว์ ส่วน Choline ได้ขึ้นทะเบียนแล้วและเฉลยระบุว่าได้รับยกเว้น ดังนั้นไม่ควรมองว่าโจทย์ทั้งสองผลิตภัณฑ์มีข้อเท็จจริงเหมือนกัน

### หลักฐานที่มีอยู่จริง

- Q-S2: ระบุความต่างของสถานะการขึ้นทะเบียนของสินค้าสองชนิด โดย Choline ได้ขึ้นทะเบียนอาหารสัตว์ควบคุมเฉพาะแล้ว
- P1-S4: มีข้อความมาตรา 81(1)(ง) ว่า “การขายปลาป่น อาหารสัตว์” เป็นถ้อยคำระดับประเภทสินค้า ไม่ใช่รายชื่อการค้าแต่ละผลิตภัณฑ์
- P1-S7: มีมาตรา 81(2)(ก) เชื่อมการนำเข้าสินค้าตาม (1)(ก) ถึง (ฉ)
- DA-S2: เป็นส่วน Application/Conclusion ที่ใช้เหตุผลว่าไม่ระบุชื่อสินค้าโดยตรง และสรุป may not be exempt
- DR-S1: คำตอบสุดท้ายตัดความไม่แน่นอนออกเป็น “ไม่ได้รับยกเว้น”

### Verifier เลือกอะไร

R และ A เลือก P1-S1 ซึ่งมีเพียงหัวมาตราและข้อความเปิดหมวด (1) ไม่ใช่เงื่อนไขอาหารสัตว์หรือการนำเข้า A เลือก Q-S1 ซึ่งยังไม่ถึงข้อความขึ้นทะเบียนใน Q-S2 และเลือก DA-S1 ซึ่งเป็นส่วน I/R ไม่ใช่ Application ที่อยู่ DA-S2 ส่วน C ก็เลือก DA-S1 มาประกอบการยืนยันว่าคำตอบตามมาจาก analysis

สิ่งที่ยืนยันได้คือหลักฐานที่รายงานไม่แสดงการตรวจจุดตัดสินสำคัญ ไม่สามารถอนุมานจาก ID อย่างเดียวว่าโมเดลไม่ได้อ่านข้อความส่วนอื่นภายใน prompt

### การวินิจฉัยของผู้ตรวจ

ข้อมูลที่มีพอให้ทักท้วงเหตุผล “ไม่ระบุชื่อสินค้า จึงไม่ยกเว้น” และการเหมารวมสองผลิตภัณฑ์ รวมถึงระดับความมั่นใจที่เปลี่ยนระหว่าง analysis กับ answer จึงไม่เหมาะให้ PASS ทุกด้านด้วยเหตุผลกว้าง ๆ

อย่างไรก็ตาม ไม่ควรเติมข้อเท็จจริงว่า GELSYS ได้รับการรับรองแล้ว เพราะคำถามไม่ได้ยืนยันเช่นนั้น และ corpus ในข้อนี้ไม่ได้มีรายละเอียดกฎหมายควบคุมคุณภาพอาหารสัตว์ครบทุกส่วน การชี้ข้อผิดในร่างกับการสร้างคำตอบครบตามเฉลยเป็นคนละระดับของความเพียงพอของข้อมูล

ข้อเสนอเชิงตรวจสอบ: พิจารณาปัญหาที่ A/C ก่อน ไม่จำเป็นต้องให้ I/R FAIL ตามกันทั้งหมด หากยังจัดประเภทสินค้าไม่ได้จากข้อมูลที่ให้ ต้องระบุส่วนที่ไม่แน่นอนแทนการฟันธงผลตรงข้าม

## ข้อ 0041: วิชาชีพตามมาตรา 40(6)

### ร่างตอบอะไร

ร่างอ้างรายการวิชาชีพในมาตรา 40(6) และเงื่อนไขวิชาชีพอื่นที่มีพระราชกฤษฎีกากำหนดได้ แต่ในส่วน Application กระโดดไปสรุปว่าผู้ได้รับใบอนุญาตวิทยาศาสตร์และเทคโนโลยีควบคุมอยู่ในหมวดนี้ คำตอบจึงเป็น “ใช่” ขณะที่เฉลยของข้อระบุว่าไม่เข้า

### หลักฐานที่มีอยู่จริง

- Q-S1: คำถามระบุวิชาชีพที่นอกเหนือจากที่กำหนดตามมาตรา 40(6) และถามว่าการรับงานนอกสังกัดทำให้เข้าหมวดนี้หรือไม่
- P1-S10: มีข้อความมาตรา 40(6) พร้อมรายการวิชาชีพและเงื่อนไขพระราชกฤษฎีกา
- DA-S1: มีส่วน I/R รวมถึงกฎดังกล่าว
- DA-S2: มี Application/Conclusion ที่จัดวิชาชีพนี้เข้าหมวดโดยไม่ยกหลักฐานรองรับเงื่อนไข

### Verifier เลือกอะไร

R/A เลือก P1-S1 ซึ่งเป็นข้อความเปิดมาตรา 40 และเงินได้จากการจ้างแรงงานใน (1) ไม่ใช่ (6) แล้วให้เหตุผลว่าใช้บทกฎหมายและประยุกต์ข้อเท็จจริงถูกต้อง A/C เลือก DA-S1 ซึ่งยังไม่ใช่ส่วน Application/Conclusion ที่มีการกระโดดข้ามเงื่อนไข

### การวินิจฉัยของผู้ตรวจ

context มีมาตรา 40(6) จริง จึงไม่ใช่กรณีไม่มีบทหลักให้ตรวจ จุดที่ตรวจพบได้คือข้อสรุปเชิงยืนยันในร่างยังไม่มีหลักฐานว่าตรงรายการวิชาชีพหรือเข้าเงื่อนไขการกำหนดเพิ่มเติม การทำงานนอกสังกัดอย่างเดียวไม่ได้เป็นหลักฐานของเงื่อนไขนั้นในข้อความที่ให้

ข้อนี้มีเหตุให้ทักท้วง Application ที่ไม่มีหลักฐานรองรับ แต่ไม่ควรอ้างจากความเงียบของ corpus ว่าไม่มีพระราชกฤษฎีกาที่เกี่ยวข้องอยู่จริงทุกฉบับ หากคำตอบที่แก้ต้องพึ่งข้อเท็จจริงนอก context ให้ระบุข้อจำกัด ไม่เติมข้อมูลให้ตรงเฉลยโดยอัตโนมัติ

R ที่คัดกฎได้ใกล้เคียงอาจไม่ใช่จุดผิดหลัก; การให้ FAIL ทุกด้านเพราะคำตอบสุดท้ายต่างจากเฉลยจะปนเกณฑ์ I/R/A/C เข้าด้วยกัน

## ข้อ 0008: กรณีเปรียบเทียบที่ข้อสรุปหลักตรงกับเฉลย

ร่างตอบว่านำดอกเบี้ยที่เกิดภาระระหว่างพักชำระหนี้มาบันทึกเป็นรายจ่ายในรอบบัญชีที่เกิดภาระได้ ข้อสรุปหลักตรงกับทั้ง reference_answer และ answer ของ dataset

หลักฐานที่รองรับอยู่ใน Q-S3: พักชำระแต่ภาระดอกเบี้ยยังเกิดและนำไปทยอยชำระในช่วงหลัง และ P1-S3: เกณฑ์สิทธิซึ่งกล่าวถึงรายจ่ายที่ยังมิได้จ่ายในรอบบัญชีนั้น

Verifier เลือก P1-S3 สำหรับ R/A ตรงประเด็น ต่างจากสองข้อข้างต้น แต่เลือก Q-S1 ซึ่งเป็นประวัติเงินยืมและเงื่อนไขสัญญาเดิม ไม่ใช่ Q-S3 ที่ระบุเงื่อนไขพักชำระและดอกเบี้ย การอ้างหลักฐานจึงยังไม่ครบถ้วนในเชิงเนื้อหาแม้ verdict หลักอาจเหมาะสม

analysis ใช้คำว่า “ยังไม่ได้รับชำระ” ขณะกล่าวถึงรายจ่าย แทน “ยังมิได้จ่าย” ตามกฎหมาย เป็นความคลาดเคลื่อนในการอธิบายที่ควรบันทึก แต่ไม่ควรบังคับแก้คำตอบหลักที่ถูกให้กลายเป็นคำตอบอื่นเพียงเพื่อให้ระบบมี FAIL

เหตุผล verifier ของข้อนี้เป็นภาษาจีน แม้ prompt ขอภาษาอังกฤษ เป็นการไม่ทำตามข้อกำหนดภาษาที่ตัวตรวจปัจจุบันไม่ได้บังคับ และเป็นคนละประเด็นกับความถูกต้องของข้อสรุป

## อะไรพิสูจน์แล้ว และอะไรยังเป็นสมมติฐาน

พิสูจน์ได้จากไฟล์:

- โมเดลสร้าง PASS ทั้งหมด; runner ไม่ได้แทนค่าคำตัดสินให้เป็น PASS
- ส่วนกฎหมายสำคัญมีอยู่ใน evidence_index ของทั้งสองข้อที่มีปัญหา
- หลักฐานที่โมเดลเลือกใน 0036/0041 ไม่ใช่ส่วนที่รองรับเหตุผลตรวจที่รายงาน
- เลือก DA-S1 มาตรวจ A/C ทั้งที่ส่วน Application/Conclusion อยู่ DA-S2
- ข้อ 0008 แสดงว่าระบบเลือกส่วนกฎหมายที่ตรงประเด็นได้อย่างน้อยหนึ่งกรณี

ยังพิสูจน์ไม่ได้:

- โมเดลเชื่อร่างเดิมมากเกินไปหรือมีอคติเลือกช่วงแรก เป็นข้อสงสัยจากพฤติกรรม ไม่ใช่ข้อสรุปเชิงเหตุ
- ความซับซ้อนของ schema, ตัวอย่าง I PASS ใน prompt, ลำดับ PASS ก่อน NonPass ใน schema หรือภาษา มีผลต่ออัตรา PASS เท่าใด
- โมเดลที่แรงขึ้น การเพิ่ม token หรือ prompt ใหม่จะแก้ได้หรือไม่
- ไม่ทราบการคิดภายในโมเดลจากเหตุผลสั้น ๆ ที่บันทึก; รายงานตรวจเฉพาะคำตอบและหลักฐานที่แสดงออกมา

## ข้อเสนอถัดไป: ยังไม่ลงมือแก้ในรอบนี้

1. เก็บ v5 เป็นผลตั้งต้น ไม่เปลี่ยน verdict ที่บันทึก และไม่ตีความ PASS เป็นคะแนน benchmark
2. ออกแบบการเปลี่ยนแบบเดียวต่อรอบที่ให้ verifier ระบุข้อกล่าวอ้างสำคัญของร่าง เลือกข้อความกฎหมายที่มีเงื่อนไขจริง แล้วระบุว่าข้อเท็จจริงเข้า/ไม่เข้า/ข้อมูลไม่พอ ก่อนสรุป verdict หลีกเลี่ยงเพียงเพิ่มคำสั่งว่า “เข้มงวดขึ้น”
3. เหตุผลของข้อเสนอคือจุดเสียที่เห็นใน trace: ปัจจุบันกรอกแหล่งหลักฐานครบได้ แต่ไม่ต้องแสดงว่าข้อกล่าวอ้างนั้นตามมาจากหลักฐานอย่างไร นี่เป็นข้อเสนอจากการวิเคราะห์ implementation ของเรา ไม่ใช่การอ้างว่าเป็นสูตรต้นฉบับของงานวิจัยใดหรือรับรองว่าจะได้ผล
4. ก่อนทำเวอร์ชันใหม่ ต้องกำหนดรูปแบบให้เล็กและตรวจงบใหม่ เพราะ schema v5 ใช้พื้นที่มากแล้ว ไม่เพิ่ม schema/จำนวนเรียกโดยไม่มีการตรวจต้นทุน หากจะอ้างความตรงกับงานวิจัย ต้องตรวจวิธีของต้นฉบับแยกก่อน
5. ทดสอบเวอร์ชันที่เสนอด้วย engineering ชุดเดิมทั้งหมดที่มีร่างครบ ไม่เลือกเฉพาะสองข้อผิด วัดทั้งการตรวจพบปัญหา การกล่าวหาว่าผิดทั้งที่ไม่มีปัญหาสำคัญ ความตรงของหลักฐาน และคำตอบก่อน/หลังแก้ รวม tokens/เวลา
6. ใช้เฉลยสำหรับประเมินภายหลังเท่านั้น; ยังไม่แตะ heldout และไม่บังคับให้ verifier มีอัตรา FAIL ตามที่ต้องการ

ไม่แนะนำขยายไป heldout เพื่อแก้ปัญหานี้ และยังไม่มีหลักฐานให้ปรับ Corrector จากรอบจริง เพราะไม่เคยถูกเรียกในผล v5 ทั้งเก้าข้อ
